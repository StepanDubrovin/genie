# Решения по платформе genie

Видение — [[platform/vision]], план — [[platform/roadmap]].

## Принятые владельцем (2026-09-28)

| № | Вопрос | Решение | Что это меняет в плане |
|---|---|---|---|
| PD1 | Модель поставки | Одна инсталляция на команду, без мультиарендности | Нет изоляции арендаторов и биллинга; одна БД сервера на команду |
| PD2 | Развёртывание | На время тестирования всё разворачивается на локальной машине; контейнеризация и облако компании — отдельный этап | MVP — бинарь сервера и pi на localhost; в MVP только каналы, которым не нужен публичный адрес; контейнеры — Ф7 |
| PD3 | Где хранить знания | Не в репозитории кода: Obsidian-подобное хранилище, как минимум отдельный репозиторий | Vault — отдельный git-репозиторий, совместимый с Obsidian ([[platform/knowledge-vault]]) |
| PD4 | Публикация документации агентами | По политике раздела | Политики `direct` / `review` / `locked`, отдельно для людей и для агентов |
| PD5 | Каналы MVP | Telegram и почта | Slack, Mattermost и другие — позже, через исходящие webhooks |
| PD6 | Проекты без кода | Поддерживаются с первой версии | Тип проекта без репозитория; команды без worktree; результат — артефакты и страницы vault |
| PD7 | Лимиты расходов на модели | Обеспечивает корпоративный провайдер, отдельно от genie | В genie нет бюджетов; остаются лимиты поведения: параллельность, частота запусков, глубина каскадов |
| PD8 | Язык бэкенда | В итоге — Go или Rust | Рекомендация — Go ([[platform/backend]]), ждёт подтверждения (PP1) |
| PD9 | Подключение через pi и других агентов | Нужно; интеграции прорабатываются отдельно | Агентский контракт (MCP + HTTP) закладывается в Ф1, адаптеры харнессов — отдельный трек |

## Предложено, ждёт подтверждения

| № | Вопрос | Предложение | Почему |
|---|---|---|---|
| PP1 | Язык бэкенда | Go | Быстрее изменения, проще надзор за процессами и развёртывание; спайк подтвердил SQLite с FTS5 без cgo ([[platform/backend]]) |
| PP2 | Порядок работ | Сначала перенос ядра на Go; новые возможности пишутся сразу на Go | Иначе журнал событий, пользователи, автоматизации и каналы пришлось бы переносить второй раз |
| PP3 | Хранилище данных | SQLite (pure-Go драйвер), сервер — единственный писатель, одна БД на инсталляцию | Нет внешних зависимостей; события и права проверяются в одном месте; Postgres — по необходимости в Ф7 |
| PP4 | Репозиторий | Монорепозиторий: Go-сервер, SPA, расширение pi, промпты ролей | Один релиз, общие контракты и тесты |
| PP5 | Веб-интерфейс | Текущая React-SPA, встроенная в бинарь | UI не переписывается; на время переноса маршруты API совместимы с нынешними |
| PP6 | Вход на этапе локального тестирования | Локальные учётки и приглашения; magic link, когда настроен SMTP; корпоративный SSO — в Ф7 | Минимум инфраструктуры на локальной машине |
| PP7 | Устройство vault | Один vault на команду, пространства по проектам | Общий граф ссылок и глоссарий; так Obsidian работает лучше всего |
| PP8 | Ревью изменений в vault | Внутри genie: ветка-предложение и экран ревью | Работает локально и не зависит от git-хостинга |
