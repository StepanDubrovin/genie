# Решения по платформе genie

Видение — [[platform/vision]], план — [[platform/roadmap]].

## Принятые владельцем (2026-09-28)

| № | Вопрос | Решение | Что это меняет в плане |
|---|---|---|---|
| PD1 | Модель поставки | Одна инсталляция на команду, без мультиарендности | Нет изоляции арендаторов и биллинга; одна БД сервера на команду |
| PD2 | Развёртывание | На время тестирования всё разворачивается на локальной машине; контейнеризация и облако компании — отдельный этап | MVP — бинарь сервера и pi на localhost; в MVP только каналы, которым не нужен публичный адрес; контейнеры — Ф7 |
| PD3 | Где хранить знания | Не в репозитории кода: Obsidian-подобное хранилище, как минимум отдельный репозиторий | Vault — отдельный git-репозиторий, совместимый с Obsidian ([[platform/knowledge-vault]]) |
| PD4 | Публикация документации агентами | По политике раздела | Политики `direct` / `review` / `locked`, отдельно для людей и для агентов |
| PD5 | Каналы MVP | Telegram и почта | Slack, Mattermost и другие — позже, через исходящие webhooks |
| PD6 | Проекты без кода | Поддерживаются с первой версии | Тип проекта без репозитория; команды без worktree; результат — артефакты и страницы vault |
| PD7 | Лимиты расходов на модели | Обеспечивает корпоративный провайдер, отдельно от genie | В genie нет бюджетов; остаются лимиты поведения: параллельность, частота запусков, глубина каскадов |
| PD8 | Язык бэкенда | Rust | Сервер и CLI — Cargo-workspace в этом репозитории ([[platform/backend]]); Go рассматривался как альтернатива |
| PD9 | Подключение через pi и других агентов | Нужно; интеграции прорабатываются отдельно | Агентский контракт (MCP + HTTP) закладывается в Ф1, адаптеры харнессов — отдельный трек |
| PD10 | Порядок работ | Сначала перенос ядра на Rust; новые возможности пишутся сразу на Rust | TS-версия остаётся рабочей до переключения (конец Ф1), на TS — только исправления |
| PD11 | Репозиторий | Пока монорепозиторий: Rust-сервер, SPA, расширение pi, промпты ролей | Один релиз, общие контракты и тесты; вопрос можно пересмотреть позже |

## Применено в MVP (без отдельного подтверждения)

| № | Вопрос | Как сделано | Почему |
|---|---|---|---|
| PP3 | Хранилище данных | SQLite (`rusqlite`), серверная БД + трекер на проект (а не одна БД с колонкой проекта) | Проекты изолированы и переносимы, TS-инструменты работают с трекером репозитория на месте; события и права — на сервере |
| PP5 | Веб-интерфейс | Текущая React-SPA; сервер раздаёт `web/dist` | UI не переписывался, маршруты API совместимы |
| PP6 | Вход | Локальные учётки, приглашения, личные токены; без пользователей — доступ только с этой машины | Минимум инфраструктуры; SSO — в Ф7 |
| PP7 | Устройство vault | Один vault на инсталляцию, пространство на проект | Общий граф и глоссарий, удобно в Obsidian |
| PP8 | Ревью знаний | Предложения и экран ревью в genie | Работает локально, без git-хостинга |
| PP9 | Запуск агентов | «Ходами»: ход харнесса на пачку писем, аренда почты до успеха хода | Нет долгоживущих процессов, которые надо пасти; рестарт ничего не теряет |
| PP10 | Интерфейс агентов | `genie agent …` поверх HTTP с токеном на ход | Работает в любом харнессе с shell; MCP — следующий шаг |
